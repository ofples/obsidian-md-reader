# Standalone reader and optional companions

This fork is the canonical maintained reader source. It can be installed without Paper, Sidebar or Supernote Transcripts. Paper distributions may include a pinned, integrity-checked copy of its artifact; reader changes belong here rather than in a second downstream patch script.

## Transcripts adapter

For each chapter, the reader checks the optional `nomad-transcripts.pageLinks` API. It supports version 1 and the older structurally compatible API with no version field. A disabled, unsupported, missing or failing adapter falls back to ordinary Obsidian Markdown rendering. Partial adapter output is cleared before fallback so text does not duplicate. The Reader does not persist native notebook paths or recognition provider credentials.

The provider accepts `element`, vault-relative `sourcePath`, exact chapter `markdown`, a canonical zero-based `sourceLineMap` (including null for synthetic lines), and the reader's render `component`. A true result means rendering is complete; false means use ordinary Markdown. New providers advertise `apiVersion: 1` and `capabilities: ['renderSection']` alongside `enabled()` and asynchronous `renderSection()`.

### Digest selection provenance

Supernote Transcripts v0.15 adds the optional `selectionProvenance` capability. Advertise it in the same version 1 capability list and provide asynchronous `selectionSource({ element, sourcePath, range })`, returning `null` or `{ path, page, pageId, pageIds, fileId? }`. `range` is a clone of the active DOM selection. The returned native note must match the local transcript mirror, and the page IDs must identify the selected text’s source pages. This capability can be used when inline page chips are hidden or page-link display is disabled. Reader requires this capability for Markdown marked `nomad_transcripts: true`; it will not send a managed transcript as a manual Markdown source when provenance is missing or fails. Ordinary Markdown does not depend on Transcripts.

### Selection actions and Android Digests

On Android, the selected-text inline menu offers **Highlight**, **Copy**, **Quick Digest**, and **Create Digest**. If a long drag leaves the menu closed, tap inside the selected excerpt to open it. Tapping an action may clear Android's blue selection, so Reader snapshots and validates the excerpt before dispatch. The separate **Save quote to Obsidian** command appends a Markdown quote and is not a native Digest action.

Both Digest actions save a persistent Reader Highlight as a separate Markdown file under `Reader Highlights` before the Bridge handoff. **Quick Digest** requests a verified native save and returns a SAVED callback to Reader while leaving Reader in front. **Create Digest** performs the same verified save, then opens the row in native Digest details; the native **Edit** control can be used there. Bridge does not show a custom capture page. First use shows one standard Android permission dialog after validating the signed request. Later trusted requests need no Bridge interaction. The Highlight remains if creation is cancelled or its outcome is uncertain.

Reader's global default is an exact native category name. Blank means use the device default, usually **Uncategorized**. A Transcripts source catalog can inherit the Reader default or set a source-specific category; an explicitly blank source override means **Uncategorized** and syncs with that catalog. Bridge refreshes the native category list and requires one exact name match before writing. A missing or ambiguous name fails before the provider insert and returns an actionable cancellation result to Reader. Source/global controls are present and Transcripts catalog behavior passes core fixtures; nondefault native category selection and two-device category sync were not tested live.

Each Highlight is a separate Markdown file with deterministic identity derived from vault-relative source path, normalized quote, and surrounding context. Optional native `fileId`/page IDs do not change that identity. Reader never modifies source Markdown or `.note` files. It paints an annotation only when the excerpt and context identify one unambiguous location; ambiguous passages remain unresolved in the Highlights manager. Saved Highlight actions include **Copy**, **Remove highlight**, and Digest handling. If this device has a local SAVED receipt, the menu also offers **Open Digest** through Bridge; the receipt is local to this device and does not sync with the annotation. Removing a Highlight removes its Markdown record, not the native Digest.

Reader signs delivery options separately from the unchanged capture payload and request ID. Bridge verifies the returned provider row before reporting SAVED, never retries an ambiguous provider write, and resolves **Open Digest** only from its local SAVED ledger. Trust and receipts are device-local. **Reconnect Quick Digest** clears Reader's local trust so first use can ask for permission again.

Sidebar remains optional. When Sidebar is installed, use version 0.4.3 or newer so its gesture handlers recognize Reader selection and saved-Highlight controls.

Ordinary Markdown uses its vault-relative file, heading, and nearby context and works without Transcripts. Managed transcript selections require Transcripts v0.15's `selectionProvenance` capability and a matching local mirror with stable native file/page IDs, even if page chips are hidden. Digest actions are Android-only; desktop Reader remains available without Bridge.

Native Digest-to-notebook navigation is unavailable. Static review of the current Knowledge 1.00.153 APK shows its source action reads an embedded Digest reference from a textbox in the `.note` file, keyed by the provider `unique_identifier`; the ordinary Digest comment URL is not a clickable backlink. Reader and Bridge do not modify original `.note` files or write that embedded reference. Existing Transcripts page chips can still open their source notebook where shown; that navigation is separate from a native Digest backlink. This is APK inspection, not a live device test.

Live ADB checks on the active local Reader, Bridge, and Transcripts candidates confirmed Quick Digest save-and-return, same-quote duplicate protection, Create Digest opening the matching synthetic excerpt in native details, missing-category cancellation without insertion, corrected same-request retry from `CANCELLED` to `SAVED` without an extra Highlight, and an exact **Uncategorized** save returning silently to Reader. The Highlight reappeared after reopening. Cleanup removed the three test Digests through individual native Details confirmations, the fixture source/folder and three owned Highlight files, and local test requests. Three Bridge audit receipts were intentionally retained; ten earlier ledger rows and trust/preferences were unchanged. The original reading location, five Reader leaves, and exact 20-position map were restored; the global category is blank. The recognition queue is idle and durably paused, automatic checks are off, and no recognition ran. The local candidates are unpublished. The Android debug candidate has versionName `0.6.0`, also used by the previous published Bridge release; that version string does not identify the candidate. Menu taps were tested; automatic menu opening after a long hardware drag was not retested. Cloud/Partner sync, rename behavior, and cross-device receipt resolution remain unverified.

The reader's optional `refreshTranscriptLinks()` hook discards prefetched decorations and rerenders while preserving position. Transcripts can notify it when the adapter loads, unloads or changes its enabled state. An unmodified MD Reader is still usable for normal Markdown; the extra adapter is needed only for validated inline notebook chips inside its custom pagination.

## Sidebar and theme

Sidebar methods are optional. Missing or failing companion navigation must leave normal reader/editor navigation available. Reader controls ship their own functional CSS. Theme fonts are a preference with normal theme/system fallbacks, not a required resource.

The plugin ID remains `md-reader` for settings and existing reading-position compatibility. Upstream MD Reader and this fork are alternatives under that same ID; install one at a time. A package must not silently overwrite either choice or replace `data.json`.

Reader code remains MIT licensed, with upstream attribution retained. Companion plugins and fonts retain their own licenses. Release preparation does not publish a release or install a candidate on a device.
