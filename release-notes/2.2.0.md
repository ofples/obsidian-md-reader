# 2.2.0

> This release note records the 2.2.0 Reader release and its original Bridge integration. The current local Bridge workflow is an unpublished candidate. Its intended path is a signed **Create Digest** request through an invisible Bridge handoff, followed by a verified saved entry in native read-only details. The first use has one standard Android permission dialog; later trusted requests need no Bridge interaction. The pinned Reader source snapshot preserves the selection through the menu click and prepares the Bridge handoff; actual native Digest creation on device still awaits confirmation.

## Selection actions

- Replaced the unclear selection glyph with labeled Digest, Highlight, and Copy actions. The original 2.2.0 Bridge release exposed **Digest** and **Digest with note…**; the current unpublished candidate presents one **Create Digest** action. Digest creation is Android-only; Highlight and Copy work on desktop too.
- Kept **Save quote to Obsidian** as a separate context-menu and command action.
- Added Reader settings for reconnecting Quick Digest after local pairing changes.

## Persistent Reader highlights

- Save highlights as separate Markdown annotation files in `Reader Highlights`, where Obsidian Sync can merge them independently of source-note edits.
- Add saved highlights after chapter rendering while preserving Markdown text, hidden page chips and page layout.
- Match by source path, quote and saved surrounding context. Ambiguous matches stay unresolved and remain visible in the Highlights manager for review or removal.
- Open a saved highlight's menu with a short tap or accessible context-menu activation. It can copy the excerpt or remove only the Reader annotation; long-press remains available for text selection. Overlapping excerpts are disambiguated.
- Offer **Create Digest** when no local receipt exists. With a local saved receipt, offer **Open Digest** through Bridge, then use the native Digest app's **Edit** action. Removing a Reader annotation does not remove its native Digest.
- Sync annotation Markdown through Obsidian Sync, while keeping native receipt associations and row IDs in per-vault local storage. A synced highlight may have no receipt link on another device.
- Save a Reader highlight before either Digest handoff. Ordinary Markdown works without Transcripts; managed transcript selections require its v1 selection-provenance capability and a matching local mirror with validated native file/page IDs.

## Digest handoff

- The original 2.2.0 Bridge integration offered Quick Digest and a separate review flow. The current unpublished Bridge candidate supports one signed Quick Digest handoff; first use asks once for permission and subsequent trusted requests save without Bridge interaction.
- Keep **Reconnect Quick Digest** to clear Reader's local pairing when it needs to enroll again.
- Keep deterministic request IDs and Bridge's duplicate-insert guard. Reopening a Reader-pending handoff checks the same request; it does not authorize a second provider insert. Uncertain provider requests are never automatically retried.
- Keep source text and Quick Digest credentials out of synced plugin settings and request-status storage.

A short tap inside already-selected text can open the same inline actions when automatic multiword menu opening after a long drag is unavailable. This shortcut leaves native long presses and drags alone. The user confirmed menu access for a selected multiword excerpt on the checked Nomad and accepted it as good enough; automatic long-drag menu behavior remains platform-dependent. The pinned Reader source snapshot retains the excerpt across menu hide and prepares the signed handoff; actual native Digest creation on device remains unverified.

## Verification

The automated suites and Nomad/provider checks recorded for this release passed, including Quick approval and reuse, the earlier detailed review flow, saved-highlight receipt opening, and native Edit. Those live Bridge results cover Bridge 0.5.1/0.6.0; they do not verify the current unpublished Bridge candidate. The pinned selection source snapshot passes 86 Chromium and 113 UI/protocol checks. A regression verifies the real selected-text tap, **Create Digest** click, menu hide and browser-selection clearing, delayed managed provenance, in-memory Highlight persistence, payload and visible annotation before Bridge dispatch. The Reader accepts the collapsed native selection left by menu hide while rejecting a changed non-collapsed range, stale action, or changed source. On the checked Nomad, the user confirmed menu access for a selected multiword excerpt and accepted it as good enough; automatic menu opening after a long drag remains platform-dependent. Actual native Digest creation on device remains unverified. Four Reader entries and 19 saved positions were preserved. The current Bridge candidate was installed in place with the same signing certificate and preserved app data, but it was not launched and no new native Digest capture was tested. No native Digest was created in this check. The native Digest backlink and Bridge's **Open original notebook**, Cloud/Partner sync, rename handling, and cross-device behavior remain unsupported or unverified as described in [native Digest notes](../docs/native-digests.md).
