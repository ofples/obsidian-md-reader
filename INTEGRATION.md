# Standalone reader and optional companions

This fork is the canonical maintained reader source. It can be installed without Paper, Sidebar or Supernote Transcripts. Paper distributions may include a pinned, integrity-checked copy of its artifact; reader changes belong here rather than in a second downstream patch script.

## Transcripts adapter

For each chapter, the reader checks the optional `nomad-transcripts.pageLinks` API. It supports version 1 and the older structurally compatible API with no version field. A disabled, unsupported, missing or failing adapter falls back to ordinary Obsidian Markdown rendering. Partial adapter output is cleared before fallback so text does not duplicate. The Reader does not persist native notebook paths or recognition provider credentials.

The provider accepts `element`, vault-relative `sourcePath`, exact chapter `markdown`, a canonical zero-based `sourceLineMap` (including null for synthetic lines), and the reader's render `component`. A true result means rendering is complete; false means use ordinary Markdown. New providers advertise `apiVersion: 1` and `capabilities: ['renderSection']` alongside `enabled()` and asynchronous `renderSection()`.

### Digest selection provenance

Supernote Transcripts v0.15 adds the optional `selectionProvenance` capability. Advertise it in the same version 1 capability list and provide asynchronous `selectionSource({ element, sourcePath, range })`, returning `null` or `{ path, page, pageId, pageIds, fileId? }`. `range` is a clone of the active DOM selection. The returned native note must match the local transcript mirror, and the page IDs must identify the selected text’s source pages. This capability can be used when inline page chips are hidden or page-link display is disabled. Reader requires this capability for Markdown marked `nomad_transcripts: true`; it will not send a managed transcript as a manual Markdown source when provenance is missing or fails. Ordinary Markdown does not depend on Transcripts.

### Selection actions and Android Digests

The selected-text toolbar and Reader context menu offer **Highlight** and **Copy** on all platforms. Android also offers **Digest** (quick) and **Digest with note…** (review). The existing **Save quote to Obsidian** action remains a separate context-menu/command workflow for appending a Markdown quote; it is not a native Digest.

Both Digest actions save a Reader highlight in the fixed `Reader Highlights` vault folder before handing the excerpt to Supernote Bridge. Each annotation is a separate Markdown file with a deterministic identity derived from the vault-relative source path, normalized quote and surrounding context. Optional native `fileId`/page IDs do not change that identity, so desktop and device Reader instances converge on the same synced annotation. `created` time is not part of duplicate identity. Reader never modifies canonical source Markdown or `.note` files. It paints an annotation only when the excerpt and saved context identify one unambiguous location; the exact full text of a single-chapter note is also safe. Ambiguous passages remain unresolved in the Highlights manager.

Saved highlight fragments are interactive. A short tap or accessible context-menu activation opens actions for **Copy**, **Remove highlight**, and Digest handling; long-press remains available to start text selection. When overlapping records cover the tapped point, Reader offers a disambiguated choice instead of combining their identities. If no local saved receipt is linked, the menu offers **Digest** (quick) and **Digest with note…** (review). With a local receipt, it offers **Open Digest** through Bridge 0.6.0 or newer; the user can then use the native Digest app's **Edit** action. Removing a Reader highlight removes only its annotation, not the native Digest.

Sidebar is optional; standalone Reader works without it. When Sidebar is installed, use version 0.4.3 or newer so its gesture handlers recognize the Reader selection dock and saved-highlight targets as controls. The checked Nomad used Sidebar 0.4.3.

Annotation Markdown files sync through the vault. Receipt-to-annotation associations and native Digest row IDs are stored locally per vault, not in synced annotation metadata, because those receipts belong to the device that created them. A synced annotation on another device therefore may have no **Open Digest** action there; it can still be copied, removed, or used to create a Digest on that device.

Reader passes the excerpt and source metadata to Bridge. The review flow always shows a confirmation before a provider insert; the user taps **Save**. On first Quick Digest use, Bridge asks for one-time approval and shows the destination list; later quick saves go to its configured default list. Return to Obsidian for an acknowledgement. Reader reports a saved Digest only after a valid callback. Reader's local `pending` status means only that it dispatched the URI and has not received a callback; reopening the same deterministic request is allowed to check Bridge's durable ledger. Reopening is not permission to attempt another provider insert: provider `PENDING` or `UNCERTAIN` blocks another insert. A saved request re-verifies its receipt, `CANCELLED` confirms no write and permits a fresh review and explicit Save, and no ledger entry begins the first Save flow. Reader stores request IDs/statuses and Quick Digest trust per vault locally; it does not sync excerpts, credentials or an account-wide ledger. If a Reader client is revoked in Bridge settings, **Reconnect Quick Digest** clears this device's local trust so Bridge can ask for approval again.

For ordinary Markdown, provenance includes the vault-relative file, heading and nearby context; this flow is independent of the Transcripts plugin. For managed transcript Markdown, the v0.15 `selectionProvenance` capability and matching local mirror with native file/page IDs are required, even if page chips are hidden. On the checked Nomad, Copy/clipboard restore, highlight persistence/reopen/removal, first-use Quick approval, trusted Quick save, detailed review with a non-default list, saved-highlight menu, receipt reopen, and native Edit passed. The detailed Bridge flow's typed note remained visible in the native Keyboard annotation tab; native Edit affected only the Digest excerpt, and the Reader annotation remained unchanged. The Reader source Markdown and `.note` files were unchanged, and no AI request was made. Cleanup is complete: all three temporary native Digests and Reader highlights were removed, the browser fixture was deleted after a SHA check, and prior reading positions and clipboard state were restored. Native Notes' Digest source action requires an embedded reference in `.note`; Transcripts and Bridge do not write that reference, so native Digest-to-notebook navigation is unsupported. Bridge's **Open original notebook** action remains unverified. Cloud/Partner sync, rename behavior, and cross-device resolution also remain unverified. Reader does not map OCR text to exact ink highlights, modify `.note` files, make AI requests, or write directly to the native database. Digest actions are Android-only; desktop Reader remains available without them. Bridge is a separate Android app; install/update availability is tracked with its own release.

The reader's optional `refreshTranscriptLinks()` hook discards prefetched decorations and rerenders while preserving position. Transcripts can notify it when the adapter loads, unloads or changes its enabled state. An unmodified MD Reader is still usable for normal Markdown; the extra adapter is needed only for validated inline notebook chips inside its custom pagination.

## Sidebar and theme

Sidebar methods are optional. Missing or failing companion navigation must leave normal reader/editor navigation available. Reader controls ship their own functional CSS. Theme fonts are a preference with normal theme/system fallbacks, not a required resource.

The plugin ID remains `md-reader` for settings and existing reading-position compatibility. Upstream MD Reader and this fork are alternatives under that same ID; install one at a time. A package must not silently overwrite either choice or replace `data.json`.

Reader code remains MIT licensed, with upstream attribution retained. Companion plugins and fonts retain their own licenses. Release preparation does not publish a release or install a candidate on a device.
